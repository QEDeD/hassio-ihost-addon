# Explicit one-attempt CPC binding for the same-app trial

Preparation only. `entrypoint.py` is a narrow trial-wrapper extension, not a CPC/s6 service and not production authorization. Its only new mode is `local_service_mode: bind-ecdh`. It delegates ordinary `prepare`/`run` to the original `state_guard.py`; a normal run is refused after an incomplete binding attempt. No shared runtime, original contribution branch, or EXECUTION record is changed here.

## Behavior

The wrapper holds the original `.local-state.lock`, reuses state_guard path validation, bounded JSON reads, atomic writes and directory fsync, and accepts only the image-owned exact device target, 115200 baud as a string, no flow control, no network-device override and no tracing. It requires compiled CPC encryption ON and a real character-device target. Existing binding key, attempt marker or completion marker causes refusal, including partial files and symlinks. It does not remove keys or attempt markers.

Before consuming the attempt or accessing the radio, it renders the existing CPC template using the installed tempio binary and verifies the resulting serial, encryption, key-path and logging fields. Current Bashio `bashio::addon.config` uses Supervisor's `/addons/self/options/config`, not an options-file override. Reusing tempio directly with four validated option fields avoids needing HA authentication or prestarting s6. The actual candidate tempio/template combination passed offline without any Supervisor token or network access.

It fsyncs a durable attempt marker before spawning exactly one CPCd process with `--bind ecdh` and the fixed key path. There is no restart/unbind/plaintext/firmware flag. The process runs in its own group with a 120-second bound; timeout, SIGINT/SIGTERM, exception and normal exit clean up that group. The single-threaded wrapper temporarily masks termination while establishing cleanup ownership, restoring the original mask in the child before exec. Raw child output is discarded with bounded buffering; only a complete vendor INFO success-marker line is recognized (optional exact ISO timestamp, then `INF : Binding successful`, newline required). Split writes are accepted; bare/misleading/malformed lines and EOF without a newline are rejected. No raw child errors, options, key bytes or hashes are printed.

Success requires normal exit0, the vendor success marker, the installed strict key preflight, key-file fsync and directory fsync, then a durably written completion marker. A failure writing/syncing the completion claim attempts to remove that claim while preserving attempt and key. The app exits without calling `/init`. Starting it again while mode remains bind-ecdh refuses; changing to run must be explicit. An interrupted/failed attempt blocks run and repeat binding. Recovery of such an attempt is intentionally not implemented.

Markers under `/data/cpc/`:

- `binding-attempt`: written before child spawn and never automatically removed.
- `binding-complete`: written only after the checked key is synced.
- `binding.key`: vendor-generated bytes, preserved unchanged, including its terminal NUL.

An abrupt SIGKILL/power loss cannot run Python cleanup. Container teardown is responsible for killing remaining processes, and the persistent attempt marker prevents another binding operation. Severe filesystem failures which prevent both syncing and removal of a completion claim require operator inspection; software cannot guarantee durable storage on a failing filesystem. The key is synced before completion creation.

## Remaining physical and operational gates

Outside the wrapper, stop every other serial owner and consumer, verify the approved device, current coherent recovery state and protected key backup destination, and approve the concrete trial. The wrapper cannot inspect another container's serial ownership. Vendor UART open alone is not an exclusive-owner guarantee.

CPC ECDH persists the radio key before returning the public-key response; host failure in that interval may leave the radio bound with no usable host key. This wrapper deliberately does not solve that by rebinding/unbinding. Successful binding alone does not prove a working encrypted endpoint, network preservation, restart persistence or recovery. Those remain separately approved acceptance checks.
