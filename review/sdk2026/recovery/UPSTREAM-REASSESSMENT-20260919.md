Native OpenThread mDNS removes the old external mDNS download patch; the pinned vendor builder replaces the old SLC archive workflow; the old mbedTLS workaround is not applied by the successful candidate recipe. Most importantly, the retained DNS patch needs adaptation: its assumption that the resolver has no RDNSS path is false in SDK2026.6.1. The subsequent authorized correction now reuses the exact merged upstream host-versus-infrastructure DNS diff. Six actual-source behavioral groups and a negative control pass; a full candidate rebuild remains required.

Nothing found supplies a tested drop-in SDK2026 multiprotocol app or a demonstrated downgrade/recovery procedure for this dongle. Existing vendor state handling, tested retained host image and backup remain the useful recovery basis. This search does not establish radio storage compatibility or counter continuity; those are the parallel recovery investigation.

## Consequential DNS semantic mismatch

Pristine SDK `OT/src/posix/platform/resolver.cpp` registers `BorderRoutingRdnssCallback` in `Setup` at lines80–86 when border routing is enabled. Candidate enables border routing. The handler at lines155–223 records RDNSS servers. `Query` around lines280–299 sends both recursive/RDNSS and host lists through shared transaction sockets; `CreateUdpSocket` around lines476–491 binds them based on one global macro. The SDK default is 1 (`openthread-posix-config.h:426`).

Before this correction, the candidate applied `0001-Route-host-upstream-DNS-through-host-routing.patch`, which sets this macro to 0 globally and says the pinned resolver has no RDNSS path. This still fixes host DNS routing, but also removes infrastructure binding from RDNSS queries. A patch applying without fuzz does not prove that old simplification remains correct. No actual production DNS failure is claimed.

PR13545 already separates an infrastructure-bound IPv6 socket for RDNSS from unbound sockets for host-configured DNS. The source patch touches resolver.cpp, resolver.hpp and openthread-posix-config.h, including socket allocation/cleanup/mainloop handling and a fallback when the bound socket cannot be created. Reuse/adapt that upstream implementation for SDK2026 and omit the old global override; test both policies and failure cleanup. No custom resolver framework or unrelated SDK source upgrade is justified. Following explicit delegated authorization, the exact upstream diff is now `../recipe/dns-routing-sdk2026.patch`; the candidate build recipe omits the old override and applies it to embedded OpenThread. Author Stefan Agner and BSD-3-Clause source license were verified. Original nine contribution implementations/branches remain unchanged.
